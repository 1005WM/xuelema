# 0.1.4 刷新入口、作业标识和框架读取

用户反馈：0.1.3 手动读取返回未完成 0、已完成 2、状态未知 0；首页刷新仍不能直接获取作业。该结果只能说明已有两条记录被分类，不能证明页面不存在其他未完成作业。

## 修改

1. **刷新入口。** 首先由 WebView 打开官方 HTML 页面 `https://mooc1-api.chaoxing.com/work/stu-work`，解析其 DOM，而非调用 JSON 私有接口。保留个人主页 → 课程的回退路径；已拿到作业时不再无条件遍历个人主页。直接入口需要额外登录跳转时先尝试个人主页，不仅凭该入口就宣布整个账号失效。
2. **作业标识。** 补充 `workHandle/handle` 链接与 `taskrefId`，仍读取 URL 中的课程与班级标识。聚合列表的标题、状态、科目分别读取 `div[role=option]` 内对应字段。`taskrefId` 只在作业路径中使用，不把同名参数的考试算成作业，也不把详情地址当成列表继续遍历。
3. **按状态分类。** 未交、未提交、未完成、未作答等归入 NOT_SUBMITTED；退回归入 RETURNED；已交、已提交、待批阅归入 SUBMITTED；已批阅归入 GRADED。无法判断保留 UNKNOWN。先读状态元素，状态元素只有截止信息时再查标题以外的行内容，作业标题不是状态证据。特定聚合模板还兼容其已知的未提交 CSS 状态标记；不会依据仅有的 `answerId=0` 推断提交状态。
4. **内嵌文档。** 使用 AndroidX WebView 的来源限定消息监听和文档起始脚本，让各个可见官方框架读取自己的 DOM，父文档只传递读取命令，遵守同源边界。只允许 HTTPS `chaoxing.com` / 子域，验证原生来源、操作随机标识和采样轮次。没有读取请求就不采集 DOM。每轮清空前轮结果，主页面导航后取消读取，外部或隐藏框架不参与。
5. **合并。** 同一次读取的文档按稳定作业 ID 去重，不因外层页面已有已完成条目就忽略内层未完成条目；明确状态冲突则报错并保留缓存。未读取的框架阻止声明全量覆盖。旧 WebView 不支持所需能力时降级为原有主页面与同源文档读取，仍可打开观察到的框架地址。
6. **入口复用。** 成功同步过的作业列表地址在当前进程按账号保存，后续刷新优先尝试；最多 8 个，不写日志或配置文件，退出登录即清空。页面新增“全部作业网页”按钮。
7. **诊断。** 结果始终附带已读文档数、框架模式、未读框架、引用链接和未完成状态文字计数。文字计数只是排查线索，不作为作业总数，统计仍只使用已经提取到稳定 ID 的记录。

## 结构依据

- [Chaoxing Assignment 作者公开的适配源码](https://greasyfork.org/en/scripts/495345-%E5%AD%A6%E4%B9%A0%E9%80%9A%E4%BB%BB%E5%8A%A1%E4%B8%80%E8%A7%88-chaoxing-assignment/code)：官方聚合作业页面地址、`ul.nav > li` / `data`、`taskrefId` 与 option 内的状态和科目结构。本项目独立实现相应读取，没有引入该脚本的其他功能。
- [AndroidX WebViewCompat](https://developer.android.com/reference/androidx/webkit/WebViewCompat)：按来源匹配文档起始脚本和消息对象。注册发生在首次加载前，旧版能力用 WebViewFeature 检查，不开放任意来源的 JavaScriptInterface。

## 验证范围

新增的聚合页面 fixture 是按公开结构手工构造的测试数据，不是用户账号页面。旧脚本在这个样例中读到 0 条，修改后读到 3 条：未完成 2、已完成 1，另一个考试条目排除。新增框架 JS 回归、原生合并与入口策略测试，以及两个不同官方来源的本地拦截网页设备测试。

构建与测试结果见 [verification.md](verification.md)。没有连接真机，设备测试只完成编译；没有真实登录账号，不能把样例通过视为用户学校页面已经验收通过。

## 使用

覆盖安装 `HomeworkAssistant-0.1.4-debug.apk` 后，先直接点首页“刷新”。也可在官方浏览器点“全部作业网页”查看读取的数据源；页面加载后仍支持“同步当前页”。

如果仍未读到未完成，新的结果会区分：官方文档是否已经读到、是否发现 taskref 引用、是否存在未完成文字但缺少可关联作业行。无需发送 Cookie、密码、API Key 或完整链接。
