# 作业完成状态自动更新（0.3.2）

日期：2026-10-29。版本：0.3.2 / versionCode 17。

0.3.3 已进一步收窄缓存恢复范围、合并重复请求，并拆开考试与详情阶段；旧版本的恢复路径和调度行为以 [当前请求范围说明](request-scope-performance.md) 为准。

旧实现的官方作业页面和首页缓存之间没有自动状态核对通路。官方提交成功只改变网页，Room 快照仍保留未提交状态，所以总数和分类必须手动刷新才更新。

## 更新行为

- 从首页打开作业后，在前台自动核对当前课程列表，完成一次核对后间隔 5 秒再查。网页加载完成会提前触发，周期核对覆盖 AJAX 提交。
- 返回首页时立即核对，必要时补查两次，间隔 1.5 / 3 秒。进入后台取消任务；返回前台恢复尚未完成的核对。退出账号和清空缓存取消并丢弃待核对任务。
- 从通用官方页面打开作业时，通过官方 URL 中的作业、课程和班级编号唯一匹配已有记录，随后启动同样的核对。编号不能唯一对应时不猜测、不批量标记完成。
- 复用有效的课程签名，只读取当前课程列表及必要分页，带新时间参数，不读取考试和作业详情；签名丢失或失效时先重新取得可信课程入口。请求沿用全局单并发与至少 1 秒间隔，单次核对最多 20 秒。
- 只有官方列表的已提交、待批阅、已批阅等状态才进入已完成。生成答案、回填、保存草稿、按钮点击或截止时间都不作为提交成功依据。官方退回也会重新归入未完成。

## 数据一致性

通过 Room 事务更新已有作业的状态字段及快照 revision，不重建整个列表、不删除其他课程、不新增已删除行。保留截止时间等详情、完整性标记和原列表同步时间，避免把单门状态核对伪装成全量刷新。状态变化后，首页总数、科目数量和分类都通过原有同一个 Flow 重新计算。

未知状态、读取失败和未返回的作业保留原数据，不推断完成。核对与全量同步、详情补充共用协调器锁及账号代次；状态变化使旧详情任务失效，防止旧任务把已提交覆盖回未提交。Room 账号键与缓存清空保护避免串账号或恢复被清掉的记录。

## 验证

- 169 项 JVM 测试通过。新增 11 项覆盖完成归档与总数、未知状态、跨课程、退回重做、重复状态、单课程请求、重启恢复、账号签名隔离、自动核对协调及读取失败保留缓存。
- 25 项不同 Android 15 模拟器用例通过：原 24 项通过后，新增自动核对链路并重跑状态测试 3 项通过。新用例验证真实 Room Flow 驱动首页、未完成转已完成而不点击刷新、账号隔离、清理后不复活；真实 AppViewModel 定期核对链路读取本地模拟官方响应并更新首页，停止后不再读取。
- Debug、Release 与设备测试 APK 构建成功；lint 0 错误 / 11 条提示。没有增加分辨率矩阵。

测试使用本地合成官方响应，没有登录实际学校账号。更新需要官方接口已经返回新状态及网络可用，通常会在数秒内核对；服务端状态传播较慢时会相应延迟。
