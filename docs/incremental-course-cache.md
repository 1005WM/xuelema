# 按课程缓存与增量更新

版本 0.3.7 / code 22，2026-10-30。保留 Kotlin、Compose、Room、DataStore 和既有 OkHttpClient / 单并发请求门控。

## 存储和更新规则

| 数据 | 实现 | 默认有效期 |
| --- | --- | --- |
| 课程目录 | 扩展既有 CourseReadCache，按账号持久化 courseId、classId、cpi、课程名、生命周期和目录成功时间 | 30 分钟 |
| 每门课程的作业 | 复用 Room homework 数据；v5 新增 course_work_cache，按账号和 courseId:classId 保存成功时间、失败提示和待更新标记 | 5 分钟 |
| 学校标识 | 沿用既有按账号入口缓存 | 2 分钟 |
| enc / stuenc | 沿用既有进程内签名缓存，不额外写入课程目录持久化存储 | 10 分钟 |

有效期定义在 ReadCacheDefaults，属于可调整的产品默认值，不代表平台安全阈值。Room v4→v5 仅新增缓存元数据表，不清空作业、考试或设置。旧安装升级后没有每课成功记录，首次刷新会读取一次，以后开始命中五分钟缓存。空作业课程也有成功记录，不能因没有作业永久跳过发现新任务。

首页订阅现有 Room Flow，网络刷新之前即展示本地数据。打开或返回首页会检查有效期，普通刷新只更新过期、失败后需重试的课程。课程目录在有效期内不重新扫描；强制刷新重查目录，并继续排除明确结课、未开放和未知状态课程。完整目录确认课程已不在当前范围时，从首页缓存中移除，晚到的状态检查不能重新恢复该课程。

成功的完整课程列表与该课程成功时间在同一个 Room 事务中发布。完整的单课结果可删除该课程已不存在的作业，保留其他课程；部分分页保留旧行且不获得新的五分钟有效期。网络失败只记录失败和待更新标记，保留旧数据、旧成功时间。缓存命中不会伪造新的成功更新时间。新的课程结果按时间防止晚到的旧结果覆盖，截止日期、满分等补充字段按已有规则合并；新日期原文不会被旧的年份日期遮盖。

## 请求复用和刷新入口

同账号、同 courseId:classId 的课程读取只有一项在途任务，刷新、页面加载、返回首页和定时提交核对共用其结果。相同模式的并发全量刷新也共用同一轮扫描，包含强制刷新。一个订阅者取消不影响其他订阅者；课程读取的最后一个订阅者离开时取消网络任务。保持原先提交状态短时间合并窗口；已生成答案、回填或保存草稿不算提交。

提交核对只读所属课程并绕过列表有效期，仍复用有效签名。只有明确的签名 / enc 失效响应才恢复该门课程签名；普通断网、超时、HTML 解析失败均不触发签名恢复或全量扫描。首次登录、切换账号按账号隔离；登录失效移除该账号的目录与签名有效性，清理缓存或退出清理相应缓存及在途任务。

当前操作课程优先，逐课程发布。考试同步和日期 / 成绩补充仍单独执行，不阻塞作业列表；已有有效截止信息且列表来自缓存的未完成作业不再重复请求详情。真实列表更新后让该课程详情重新获得补充机会，以便发现截止时间修改。考试沿用已有本地时间，五分钟内普通作业刷新不重复拉考试；强制全量刷新重新同步考试。

首页右上角“⋮”提供三个入口：

- 刷新过期课程：与总览刷新按钮、下拉刷新相同，遵循目录与课程有效期。
- 刷新当前课程：选择科目或打开过该课程作业后可用，绕过该门数据有效期；有效目录和签名仍复用。
- 强制全量刷新：绕过目录与课程数据有效期，保留请求合并、签名复用、单并发与限流规则。

首页显示上次成功更新时间；当前课程区分本地缓存、已更新、更新中和更新失败，并保留缓存卡片。0.3.8 按用户要求移除首页红色详细同步结果段落；同步结果浮层和验证恢复入口保留。

## 暂停和服务器等待

共享 PlatformReadGate 保存暂停原因与等待截止时间。429 不立即重试，也不转为签名失效；Retry-After 支持整数秒和 RFC 1123 HTTP 日期。带等待头的 502/503/504 也暂停，其他可重试的临时错误保留既有有限重试。403、明确的权限限制、人机验证暂停自动请求；页面完成验证后由用户点击“验证后重试”或重新验证登录恢复。等待时间未到时，这个入口、强制刷新及进程重启都不能清除服务器要求的等待。

暂停记录在设备持久化，跨账号也保留尚未结束的服务器等待，防止切换账号意外绕过限流。不绕过验证码，不增加 HTTP 并发，不创建新的平台客户端。
