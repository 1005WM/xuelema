# 填空与简答答案框回填修复（0.2.6）

日期：2026-10-28。版本：0.2.6 / versionCode 12。

用户反馈：AI 可以生成答案，但填空题和简答题不能写入答案框。没有收到真实网页 HTML，因此本轮修复的是代码中已复现的兼容缺口，仍需在用户学校的实际作业页验证。

## 已复现的问题

0.2.5 的上游 UEditor 适配只接受 `/work/doHomeWorkNew` 及 `form#form1` 等特定结构。新版作业地址和其他表单 ID 即使拥有同题唯一、已经就绪的编辑器实例，也被判定为不能预填。新增回归用例在旧代码下得到 `canFill=false`，与预期不符。

普通 `contenteditable` 和没有 UEditor 注册实例的可编辑 iframe 没有写入路径。另外，AI 生成期间编辑器从“未就绪”变为“就绪”时，原快照把能力和关联变化视为题目变化，阻止后续写入。

## 修复

- 新增 `assets/scripts/question_text_adapter.js`，通过原有编辑器实例、唯一 textarea、题目根节点、iframe 文档和表单归属定位 UEditor，不再依赖单个网址或固定表单 ID。不创建或猜测编辑器实例。
- 支持题目内唯一的 `contenteditable=true`，以及可访问且唯一的可编辑 iframe 正文。触发原生 `input` / `change` 事件。存在保存字段时等待同步；不同步则明确显示“待检查”并停止后续回填。
- 回填前重新解析控件。题目文字、选项、材料、原控件身份及作答区域必须保持一致；仅允许编辑器就绪等可确认的能力变化。题目、控件、已有编辑器实例或原生保存关联被替换时仍拒绝操作。
- 单空填空接收 JSON 单元素数组并取出答案文本，避免将数组语法填入答案框。多元素数组不向单个空盲目写入。
- 不覆盖已有不同手工作答，不写入只读控件，不猜测多个无明确关联的文本框或混合作答控件。模型文本通过文本节点及换行写入，不作为 HTML 执行。
- BottomSheet 的结果和错误可滚动、选择与复制，不再被固定 5 行截断；编辑器初次未就绪时提示回填阶段会重新检查。
- WebMessage 回复前增加显式特性检查，消除上版两条 RequiresFeature 提示。

上游三个 MIT 模块保持原样，适配代码通过独立扩展加载；生产 Kotlin 装载器和 JS 测试使用相同的组合顺序。

## 使用

覆盖安装 `dist/HomeworkAssistant-0.2.6-debug.apk`，保留账号与 AI 配置。重新进入作业，生成答案后点击“回填页面”，核对官方页面并手动保存或提交。若编辑器仍在加载，可等待后再次回填，无需为同一页面重新调用 AI。

## 验证范围

- 15 个新文本回填回归：新版地址/表单、UEditor、延迟就绪、控件替换、contenteditable、手工作答保留、只读、题干变化、保存字段同步/不同步、可编辑 iframe、多控件歧义、JSON 单空、混合控件、保存字段替换。
- 原 AI 引擎的 25 个场景继续通过，包括选择题、多空关联与富文本文本转义；既有作业列表 JS 回归通过。
- Kotlin 单元测试与构建结果见 [verification.md](verification.md)。没有连接真机，没有调用真实 AI 服务；合成用例不能证明所有学校页面已适配。
